# Product Brief: AI Study Buddy

## Executive Summary

AI Study Buddy is a single-user web app that turns lecture slides and notes into accurate, ready-to-use study summaries. Abdiaziz uploads a PDF (or pastes text) from his course material, picks a summary length and language, and gets a clean, structured summary back — generated by an LLM (Google Gemini, free tier) via a simple Streamlit interface.

This is Abdiaziz's IBE160 (Programmering med KI) course project at Høgskolen i Molde, built solo. V1 is deliberately narrow: one feature (summarization) done well, rather than three features done half-finished. Flashcard and quiz generation from the lecturer's original proposal are kept as stretch goals, added only if time allows once summarization works reliably.

Beyond the grade, this is a tool Abdiaziz intends to actually use on his own coursework this semester and beyond — and, if it proves useful, open it up to other students later.

## The Problem

Processing dense course material — PDF slides, lecture notes, syllabus documents — is slow and mentally taxing. Turning that raw material into something actually useful for studying (a concise, accurate summary at the right level of detail) is manual, repetitive work that eats time students don't have much of, especially across multiple courses at once.

Existing generic AI chat tools can summarize text if you paste it in, but they aren't built for this workflow specifically: no PDF upload, no control over summary length, no language choice tuned to how Norwegian students actually study, often with a mix of Norwegian and English material.

## The Solution

A focused web app: upload a PDF or paste text → choose summary length (short / medium / long) and output language (Norwegian or English) → get back a structured, accurate summary. Built with Streamlit (Python) and powered by the Google Gemini API (free tier).

V1 scope is intentionally narrow — summarization only — so it can be built well by one person new to programming, within a semester. Flashcard generation and quiz generation (from the same lecturer-proposed idea) are explicit stretch goals, using the same underlying pipeline (parse material → LLM call → structured output), to be added after summarization is solid.

## Who This Serves

**Primary user: Abdiaziz**, studying IBE160 and other courses at Høgskolen i Molde. His course material is mostly PDF slides and notes, often in Norwegian. He needs quick, reliable summaries at varying levels of detail, in either Norwegian or English, without manually rereading and condensing everything himself.

**Secondary user (future, not this semester): other students.** Abdiaziz is building the app single-user on purpose — no accounts, no multi-tenancy — but the underlying design shouldn't require a rewrite if it's later opened up to classmates.

## Scope

**In scope for v1:**
- PDF upload (text-based PDFs — lecture slides/notes) and pasted-text input
- Summary generation with user-selectable length (short/medium/long) and language (Norwegian/English)
- Clean, simple Streamlit UI
- Documentation explaining how the app and its AI use work (for both the course submission and Abdiaziz's own understanding)
- Single-user only — no accounts or authentication needed at this scope (see "Explicitly out of scope" below)
- Deployment on Streamlit Community Cloud (free tier) or run locally

**Stretch goals (post-v1, only if time allows):**
- Flashcard generation from the same uploaded material
- Quiz question generation (with answers) from the same uploaded material

**Explicitly out of scope for this project:**
- Scanned or image-based PDFs requiring OCR
- Complex table/figure extraction and handling
- Multi-user accounts, login, or encrypted storage
- Languages other than Norwegian and English
- Any paid API usage (free tier only)

- **Tech constraint**: Lecturer's proposal document specifies no required technology or framework
- **Deliverables & milestones**: **TBD.** The separate course syllabus/plan has not been reviewed yet. Current assumption — a working app plus some form of writeup or demo by mid-December — should be confirmed against the actual syllabus and this brief updated accordingly

## Success Criteria

**Product/grading quality:**
- Working, easy-to-use app
- Accurate, genuinely useful summaries
- Clean interface
- Demonstrable, thoughtful prompt engineering (not a naive pass-through prompt)
- Clear documentation explaining how the app and its AI use work

**Personal:**
- Abdiaziz genuinely understands the Python code he writes — not just working output he can't explain
- He actually keeps using the app on his own coursework after the semester ends

## Risks & Open Questions

- **PDF parsing reliability**: varied slide/note formatting could break naive parsing. Mitigated by scoping v1 to text-based PDFs only (no scanned/image PDFs, no complex tables/figures).
- **Summary accuracy**: quality depends heavily on prompt engineering; will need iteration and real testing against Abdiaziz's actual course material.
- **New to Python**: general learning-curve risk for a solo build. Mitigated by choosing a low-friction stack (Streamlit) and a narrow v1 feature set (summaries only, flashcards/quizzes deferred).
- **Gemini free-tier rate limits**: could interrupt development or a live demo. Needs monitoring; may require request throttling or caching during heavy testing.
- **Deliverables/milestones unknown** (see Course Context & Constraints above): needs checking against the actual course syllabus soon, and this brief updated once confirmed.

## Vision

If AI Study Buddy proves genuinely useful this semester, the natural next steps are the deferred features — flashcards and quizzes — followed by opening it up to other students with basic accounts, and eventually supporting organization across multiple courses. None of this is committed for the course project, but the single-user v1 is designed so it doesn't need a full rewrite to get there.
