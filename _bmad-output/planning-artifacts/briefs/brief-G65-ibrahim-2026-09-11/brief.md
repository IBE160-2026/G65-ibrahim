# Product Brief: AI Study Buddy

## Executive Summary

AI Study Buddy is a single-user web app that turns lecture slides and notes into accurate, ready-to-use study summaries and a short self-test quiz. Abdiaziz uploads a PDF (or pastes text) from his course material, picks a summary length and language, and gets back a clean, structured summary plus a quiz with an answer key — generated by an LLM (Google Gemini, free tier) via a simple Streamlit interface.

This is Abdiaziz's IBE160 (Programmering med KI) course project at Høgskolen i Molde, built solo. V1 covers two features done well — summarization and quiz generation with an answer key — rather than three features done half-finished. Flashcard generation from the lecturer's original proposal is kept as a stretch goal, added only if time allows.

Beyond the grade, this is a tool Abdiaziz intends to actually use on his own coursework this semester and beyond — and, if it proves useful, open it up to other students later.

## The Problem

Processing dense course material — PDF slides, lecture notes, syllabus documents — is slow and mentally taxing. Turning that raw material into something actually useful for studying (a concise, accurate summary at the right level of detail, plus a quick way to check whether it was actually absorbed) is manual, repetitive work that eats time students don't have much of, especially across multiple courses at once.

Existing generic AI chat tools can summarize text if you paste it in, but they aren't built for this workflow specifically: no PDF upload, no control over summary length, no language choice tuned to how Norwegian students actually study, often with a mix of Norwegian and English material, and no built-in way to self-test against the material afterward.

## The Solution

A focused web app: upload a PDF or paste text → choose summary length (short / medium / long) and output language (Norwegian or English) → get back a structured, accurate summary plus a short quiz with an answer key to self-test against. Built with Streamlit (Python) and powered by the Google Gemini API (free tier).

Pairing summarization with quiz generation gives enough real functionality, testing, and process to show for a solo, beginner project. Flashcard generation (from the same lecturer-proposed idea) is an explicit stretch goal, using the same underlying pipeline (parse material → LLM call → structured output), to be added after the core features are solid.

## What Makes This Different

This is a convenience and workflow tool, not a capability no other AI product has — it's worth being honest about that. Generic AI chat tools (ChatGPT, Gemini's own chat interface, etc.) can already summarize a document if you paste or upload it there. What AI Study Buddy adds is a workflow tuned specifically to studying from course material: direct PDF upload without manual copy-paste, explicit control over summary length and output language (useful when working across Norwegian and English material in the same course), and a quiz with an answer key generated from the same material in the same pass — without re-prompting a chatbot each time. The value is in removing friction from a repeated task, not in a unique AI capability.

## Who This Serves

**Primary user: Abdiaziz**, studying IBE160 and other courses at Høgskolen i Molde. His course material is mostly PDF slides and notes, often in Norwegian. He needs quick, reliable summaries at varying levels of detail, in either Norwegian or English, without manually rereading and condensing everything himself.

**Secondary user (future, not this semester): other students.** Abdiaziz is building the app single-user on purpose — no accounts, no multi-tenancy — but the underlying design shouldn't require a rewrite if it's later opened up to classmates.

## Scope

**In scope for v1:**
- PDF upload (text-based PDFs — lecture slides/notes) and pasted-text input
- Summary generation with user-selectable length (short/medium/long) and language (Norwegian/English)
- Quiz generation with an answer key from the same uploaded material: at least 5 questions per document, student submits answers and sees which were correct
- Clean, simple Streamlit UI
- Documentation explaining how the app and its AI use work (for both the course submission and Abdiaziz's own understanding)
- Single-user only — no accounts or authentication needed at this scope (see "Explicitly out of scope" below)
- Deployment on Streamlit Community Cloud (free tier) or run locally
- Secrets handling: Gemini API key stored via `.env` or Streamlit `secrets.toml`, both gitignored and never committed; a `.env.example` with placeholder values is committed instead
- A small set of test documents (Norwegian PDF, English PDF, mixed-language text, scanned/invalid PDF) kept in a dedicated test-data folder, separate from source code
- README that lets someone unfamiliar with the project run the app locally end-to-end, including how to obtain a free Gemini API key (no credit card required) from Google AI Studio; a test mode with a saved example response is considered as a fallback if API-key friction for graders turns out to be a problem

**Stretch goals (post-v1, only if time allows):**
- Flashcard generation from the same uploaded material
- Storage of past summaries/quizzes per subject (e.g. local SQLite), to build up a collection over the semester

**Explicitly out of scope for this project:**
- Scanned or image-based PDFs requiring OCR
- Complex table/figure extraction and handling
- Multi-user accounts, login, or encrypted storage
- Languages other than Norwegian and English
- Any paid API usage (free tier only)

## Success Criteria

**Functional (testable):**
- A "short" summary is under 150 words; "medium" is 150–400 words; "long" is 400–800 words
- Selecting English as output language always returns an English summary, even when the source PDF/text is in Norwegian (and vice versa for Norwegian output)
- A scanned/image-only PDF with no extractable text produces a clear, understandable error message instead of crashing or returning an empty result
- An invalid or empty upload (wrong file type, 0-byte file) is rejected with a clear error message
- Quiz generation produces at least 5 questions per summarized document, each with a stored correct answer; the student can submit answers and see which were correct against the answer key
- A typical lecture PDF (10–20 slides) returns both summary and quiz within a reasonable wait (e.g. under 30 seconds) under normal Gemini free-tier conditions
- The README lets someone unfamiliar with the project run the app locally end-to-end without errors, using only the setup steps described

**Product/grading quality:**
- Demonstrable, thoughtful prompt engineering (not a naive pass-through prompt)
- Clear documentation explaining how the app and its AI use work

**Personal:**
- Abdiaziz genuinely understands the Python code he writes — not just working output he can't explain
- He actually keeps using the app on his own coursework after the semester ends

## Risks & Open Questions

- **Deadline risk**: the final submission is reported as due now or overdue, with the exact syllabus date and deliverable format still unconfirmed. Highest-priority open question — confirm immediately and adjust scope down further if needed.
- **PDF parsing reliability**: varied slide/note formatting could break naive parsing. Mitigated by scoping v1 to text-based PDFs only (no scanned/image PDFs, no complex tables/figures).
- **Summary accuracy**: quality depends heavily on prompt engineering; will need iteration and real testing against Abdiaziz's actual course material.
- **New to Python**: general learning-curve risk for a solo build. Mitigated by choosing a low-friction stack (Streamlit) and a v1 feature set limited to summaries and quiz generation (flashcards/storage deferred).
- **Gemini free-tier rate limits**: could interrupt development or a live demo. Needs monitoring; may require request throttling or caching during heavy testing.
- **Examiner runnability**: grading requires a free Gemini API key. Mitigated by documenting key setup in the README and considering a canned-response test mode as a fallback.

## Vision

If AI Study Buddy proves genuinely useful this semester, the natural next steps are the deferred features — flashcards and per-subject storage of past summaries/quizzes — followed by opening it up to other students with basic accounts, and eventually supporting organization across multiple courses. None of this is committed for the course project, but the single-user v1 is designed so it doesn't need a full rewrite to get there.
