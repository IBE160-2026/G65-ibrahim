Spine validation: AI Study Buddy

2026-11-16 · ARCHITECTURE-SPINE.md (final, b9a5d76) · spine not changed · lint clean · 3 lenses run one at a time
The paradigm, module boundaries, the single Gemini request and the pinned stack hold up, and every pin is current and installs together on Python 3.13. The holes are all on the app.py side: session state, the fingerprint, the st.secrets hand-off, and Gemini timeouts/network errors under google-genai 3.x. Stories built separately against the spine as it stands would crash at startup in one case and disagree silently in several others. Fix these before Story 1.1.
1 critical 4 high 9 medium 6 low

Critical

C1: App crashes at startup without secrets.toml adversarial H1

AD-9 passes st.secrets to config.load_settings. With no secrets file (a grader using only .env), reading it raises a Streamlit error that config.py can't catch without importing Streamlit, which AD-1 forbids.
Fix (AD-9): app.py converts st.secrets to a dict inside try/except, falling back to {}.

High

H1: Quiz count, "at least 5" vs "exactly 5" rubric F1 · adversarial H9

AD-3 allows 5 or more questions, but the UX and stories hard-code 5 ("You got X of 5 right", questions 1–5).
Fix (AD-3): exactly 5 questions. That still meets the PRD's "at least 5".

H2: Session-state contract is incomplete rubric F2 · adversarial H3 H4 H5 H8 H10

  • Missing keys: widget keys (tabs, radios, toggle), a running flag, and the Length/Language used for a result. Without that last one, the caption contradicts stale and demo results.
  • Radio state: the quiz radios keep their own state, so clearing quiz_answers doesn't clear them. st.radio returns option text, not an index.
  • Value types: study_pack could be stored as a StudyPack or as a dict.
  • Failure timing: it isn't said whether Generate clears state on click or only on success.
Fix (rewrite AD-7): list app keys and widget keys separately; add generated_with and generation_id; radio keys include generation_id and a quiz_round counter, with options as indices 0–3; study_pack is always a StudyPack; state changes only after a successful generation.

H3: The fingerprint is underspecified rubric F3 · adversarial H2

It isn't said whether the fingerprint hashes raw input or extracted text, whether the active tab counts, which hash to use, or what demo mode hashes. As a result the stale-results note ends up always on or never on.
Fix (new AD-12): a core function input_fingerprint(active_tab, raw_value, length, language, demo) hashes the active tab's raw widget value with SHA-256, at Generate and on every rerun.

H4: Timeouts and network errors under google-genai 3.x version VC-1 VC-2 · rubric F5

The default timeout is None, and network and timeout failures arrive as httpx2 exceptions, not errors.APIError. As specified, the "Couldn't reach Gemini" path can't happen.
Fix (AD-4, AD-5): HttpOptions(timeout=60_000) (milliseconds); map httpx2.TimeoutException and ConnectError to GeminiUnavailable.

Medium

M1: Uncovered failures rubric F4 · version VC-9

Encrypted and corrupt PDFs, a Gemini 400 for oversized input, a safety block or empty reply, and an invalid demo JSON file.
Fix: map each to an existing error type or a new one (e.g. UnreadablePdf).

M2: Tested helpers sit in app.py rubric F6

Word count and the fingerprint must be tested, but the shell isn't.
Fix: move them into a core module.

M3: Error messages are split across stories adversarial H10

Stories 1.2, 1.4 and 3.1 each touch the message text and style.
Fix: one ERROR_UI table (text + error/warning style) in app.py.

M4: Enum ↔ label ↔ prompt wording adversarial H6

Fix: one mapping in models.py; fixed placeholder names {word_range}, {language_name}, {material}.

M5: ingest() signature adversarial H7

Fix: from_pdf(name, data: bytes) and from_text(text); NotPdf = no .pdf extension or bytes not starting with %PDF.

M6: LLM validation and test seam rubric F7

Fix: StudyPack.model_validate_json(response.text); tests replace llm._call_gemini(prompt, settings) -> str.

M7: Unpinned transitive dependencies version VC-6

Community Cloud picks fresh starlette/uvicorn versions on every deploy.
Fix: freeze the full set before Story 3.2.

M8: Operational envelope only in the memlog rubric F8

Privacy disclosure, model-deprecation plan, manual Python 3.13 choice, throttling.
Fix: add to Deployment and Deferred.

M9: Structured output on API v1 not smoke-tested version VC-3

Fix: one real smoke call in Story 1.3's manual checks.
